# Firebase Crashlytics owner setup

Prelude+ contains an opt-in Crashlytics integration, but it is intentionally
inactive until the publisher connects a Firebase project. Google Analytics is
not part of this integration.

## What the owner gets

After setup, the Firebase owner can use **Firebase Console > Crashlytics** to
inspect grouped crashes, affected app versions, stack traces and Android 11+
ANRs. Console access is controlled by the Firebase project's IAM members; app
users never receive owner access.

## One-time setup

1. Create a Firebase project owned by the same Google account or organization
   that will publish Prelude+.
2. Do **not** enable Google Analytics when creating the project.
3. Add Android app `com.prelude.iptv`.
4. If QA reports are also required, add a second Android app with package
   `com.prelude.iptv.qa` to the same project.
5. Download the generated `google-services.json` and place it at
   `app/google-services.json`.
6. Keep that local file outside source control. The repository ignores it.
7. Build a fresh QA/release artifact. The Gradle plugins are applied only when
   the configuration file exists.
8. On a test device open **Settings > Diagnostics & crashes**, enable reporting,
   then validate with a controlled test failure before any public release.

## Privacy behavior

- Firebase does not initialize before the user opts in or explicitly chooses to
  send one pending report.
- Automatic collection is disabled in the manifest.
- With reporting off, Prelude+ stores one redacted crash summary in private app
  storage. It is never uploaded automatically.
- The app does not attach playlist URLs, provider credentials, media titles,
  profile identifiers or navigation breadcrumbs.
- Automatic Crashlytics reports can still contain the exception type/message,
  stack trace, app/device/OS information and ANR diagnostics generated by the
  SDK. This is disclosed in the privacy policy.
- Turning reporting off deletes Crashlytics reports waiting on that device.
- Google Analytics and advertising identifiers are not included.

## Release checks

- Confirm `FIREBASE_CRASH_REPORTING_CONFIGURED=true` in the generated BuildConfig
  for the intended variant.
- Confirm reports are absent before consent and arrive after consent.
- Confirm release mapping upload succeeds so minified stack traces are readable.
- Restrict Firebase project membership to the publisher and trusted developers.
- Keep the in-app privacy text, public privacy URL and Play Data safety form in
  sync with the shipped behavior.
